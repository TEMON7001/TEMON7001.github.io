# Мини-приложения (GitHub Pages)

Репозиторий обслуживает корень домена `https://temon7001.github.io/` — это обязательное условие
для Digital Asset Links: TWA-обёртка проверяет файл строго по адресу
`https://temon7001.github.io/.well-known/assetlinks.json`, а репозиторий проекта
(вида `github.com/TEMON7001/что-угодно`) отдаёт страницы по пути `/что-угодно/` и корень домена
обслуживать не может.

## Структура

```
/                       корневая страница со списком мини-приложений
/.nojekyll              отключает Jekyll — без него Pages не публикует .well-known
/.well-known/assetlinks.json   связка сайта и Android-приложений (по одному блоку на приложение)
/electro/               «Расчёт сечения по ПУЭ» — PWA
/can-decoder/           «CAN Дешифратор» — PWA
/remont/                «Ремонт комнаты» — PWA, но в RuStore идёт не через TWA
```

Файл `.nojekyll` удалять нельзя. GitHub Pages по умолчанию прогоняет репозиторий через Jekyll,
а Jekyll не копирует в сборку файлы и папки, начинающиеся с точки, — то есть `.well-known/`
просто не попадёт на сайт и `assetlinks.json` отдаст 404. Пустой `.nojekyll` в корне выключает
эту обработку.

## Ремонт комнаты — исключение из правил

Приложение №3 обёрнуто не в TWA, а в собственную Android-обёртку: WebView на весь экран
и нативный баннер рекламной сети под ним. Из TWA рекламный SDK вызвать нечем — TWA открывает
сайт чужим браузером.

Отсюда два отличия, которые легко нарушить по привычке:

- блок в `.well-known/assetlinks.json` этому приложению **не нужен**: Digital Asset Links
  проверяет TWA, а обёртка грузит файлы из своих assets;
- правка в `/remont/` **не доезжает** до установленного приложения. На сайте она появится
  сразу, в APK — только с новой сборкой. Файлы копируются в assets обёртки при сборке.

Сама обёртка лежит не здесь, а в закрытом репозитории `RuStore/apps/`: этот репозиторий
публичный, и исходникам сборки под магазин в нём не место.

## Добавление следующего мини-приложения (TWA)

1. Положить PWA в новую папку (`/can/`, `/sad/` и т. д.), `scope` и `start_url` в manifest.json — абсолютные,
   от корня домена.
2. Собрать APK в PWABuilder по адресу `https://temon7001.github.io/<папка>/`.
3. Добавить в `/.well-known/assetlinks.json` **ещё один блок** массива со своим `package_name`
   и своим SHA-256 (файл — массив, приложений в нём может быть сколько угодно).
4. Добавить карточку приложения в корневой `index.html` со строкой `<span class="ver">сборка N</span>`.

## Номера сборок

В карточках на корневой странице показан номер сборки — он берётся из `CACHE_NAME` в `sw.js`
соответствующего приложения (`electro-calc-v8` → «сборка 8»).

Сторовая версия для этого не годится: APK — пустая оболочка, она грузит сайт, поэтому версия
в RuStore не меняется, когда меняется само приложение. Номер сборки меняется всегда.

**При каждом релизе поднимать оба места сразу:** `CACHE_NAME` в `sw.js` и `сборка N` в корневом
`index.html`. Это единственная пара значений в репозитории, которую нужно держать в синхроне вручную.

## Проверка

- Манифест доступен: `https://temon7001.github.io/electro/manifest.json`
- Assetlinks отдаётся как JSON: `https://temon7001.github.io/.well-known/assetlinks.json`
- Проверка связки: `https://developers.google.com/digital-asset-links/tools/generator`
